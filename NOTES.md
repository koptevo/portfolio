## Стек и почему именно он

**Чистый HTML + CSS + JavaScript. Никаких зависимостей, никакой сборки.**

- Файл открывается в браузере как есть — не нужен Node.js, npm, терминал.
- Можно править в VS Code и сразу видеть результат.
- Хостинг бесплатный и не сломается через год из-за устаревших пакетов.
- Клиенту можно отдать ссылку или архив — он не зависит от твоей машины.

Сознательный выбор против React/Tailwind/сборщиков: для одностраничника они дают только сложность.

## Принятые решения

### Дизайн

- **Палитра:** почти чёрный фон `#0a0a0b`, тёплый белый текст `#f7f4ee`, оранжевый акцент `#ff6a28`.
  Меняли с исходной светлой «бумажной» темы на чёрную по запросу.
- **Референс:** [femmefatale.paris](https://www.femmefatale.paris) — огромные заголовки с плотным трекингом,
  нумерованные подписи секций (`01 — Подход`), точки в конце пунктов меню, бегущая строка, зерно на фоне.
  Взят **принцип**, не копия.
- **Плавная прокрутка** — своя, на `requestAnimationFrame` с интерполяцией (похоже на Lenis),
  вместе с появлением/уходом секций в одном цикле. Отключается на тач-устройствах
  (`pointer: coarse`) и при `prefers-reduced-motion` — чтобы не было тошноты и лагов.

### Содержание

- **Без имени и фамилии на сайте.** Ни в шапке, ни в подвале, ни в мета-тегах.
  Причина: страницу видят незнакомые люди, а имя ничего не добавляет к продаже.
  Вместо бренда — нейтральное `мастерская·сайтов`.
- **Без выдуманной команды.** Никаких «наша команда из 5 специалистов» — враньё вскрывается на первом созвоне.
  Формулировки обезличенные: «Брифинг», «Показ», «Сдача».
- **Тон:** сдержанный, короткие фразы, без восклицательных знаков и «уникальных предложений».

## Технические тонкости, на которых уже спотыкались

Это грабли, на которые легко наступить снова. Записаны, чтобы не повторять.

1. **Кнопка «наверх» не работала**, потому что `id="top"` висел на `position: sticky` шапке — переход к ней ничего не делал.
   Теперь `id="top"` на `<body>` + `scroll-margin-top`.
2. **Бегущая строка оставляла дыру** на широких экранах: контент дублировался один раз, а нужно минимум два экрана.
   Теперь число копий считается от ширины окна и всегда чётное, скорость — `половина_ширины / 50` пикселей в секунду.
3. **Заголовок главного экрана вылезал за экран** на низких ноутбуках (900 px).
   Размер шрифта: `clamp(46px, min(13.2vw, 16.4vh), 186px)` — учитывает и ширину, и высоту.
4. **Карточки работ были слишком высокими**, подписи уезжали за край. Лечится `aspect-ratio` + `max-height: 460px` + `width: 100%`.
   Если убрать `width: 100%` — карточка сжимается по ширине.
5. **Форма в демо барбершопа:** поле нельзя доставать как `form.name` — это вернёт имя самой формы.
   Только `form.elements.namedItem('name')`.
6. **`?static` в адресе** отключает плавную прокрутку и входные анимации. Нужно для скриншотов,
   иначе кадр ловится в середине анимации. Обычным посетителям не мешает.

## Как работать с проектом

**Посмотреть локально:** в VS Code расширение Live Server → правый клик по `index.html` → `Open with Live Server`.
Адрес обычно `http://127.0.0.1:5500/`.

**Обновить сайт после правок:**

```
git add -A
git commit -m "что изменил"
git push
```

GitHub Pages пересобирается примерно за минуту, страницу обновлять с `Ctrl+F5`.

**Важно:** в VS Code сохранять файл перед обновлением браузера (`Ctrl+S`).
Точка в заголовке вкладки означает, что изменения ещё не записаны на диск.
